# North Star — Program Destination

This file is the canonical, pinned goal of the supervisor program. Humans read the prose; machines read the fenced YAML block below and its sha256 pin in `docs/program/pins.json`. **Do not edit this file without an amendment record** (see Amendment protocol) — the guard test and, once the slice lands, gate-start hash checks will fail on any unpinned change. Agent runs must treat this path as never-touch.

## Destination

> The supervisor's value is settled by evidence: a powered, paired, independently-graded experiment — every grade signed by a principal the harness does not control, every claim provenance-closed — answers whether supervisor-on beats compute-matched supervisor-off, and that answer, **either way**, is published with its full evidence chain.

Every planning session orients to this before choosing work. Work that does not advance a clause below is out of scope for this effort and must be ruled so explicitly, not absorbed silently.

## Clause → existing machinery map

C1 → `experiment_kernel` preregistered ExperimentSpec + assignments; powered-analysis requirement in `claim_gate` (L3). C2 → `claim_gate` producer≠verifier check + `swe_bench_official_oracle` trusted-backend authority validation. C3 → trace-graph closure rules + fail-closed evidence resolution in `claim_gate`. C4 → `Arm.C (compute_matched_direct)` present with `primary_comparison=(B,C)`. C5 → FrozenTaskResult + report carrying a derived claim level. The `destination_gate` slice composes these; it introduces no new judgment logic.

## Stage doctrine (compressed)

Intent is testable before execution and hash-pinned during it (acceptance criteria + agreed seams). Execution runs with proven-ready capabilities (pre-flight canaries on pinned lanes) inside recorded sandboxes. No claim is accepted without closed provenance; self-report is never evidence. Review is blinded-first (spec and standards axes), adjudication outcome-aware and last, rendered from the evidence chain. Ship only what hash-matches what was approved. Measurement against an independent grader precedes and outlives every feature. The harness evolves only through curated external solutions that beat both nothing and the incumbent, under control arms (no-op, human, standard optimizer), promoted by humans, attributable and reversible per overlay slot.

## Graduated human withdrawal

Attention is the bootstrap phase of the trust chain, not a cost. While the operator reviews, the harness shadows every human decision and records agreement. Phases: (1) review everything, harness shadows; (2) review all rejections + declining sample of acceptances — unlocks when shadow-agreement ≥ T₁ over N₁ decisions AND sampled false-accept rate ≤ F₁; (3) exceptions only (judge disagreements, regressions, novel task classes) + standing weekly audit; (4) two touchpoints (experiment activation, promotion approval). Rules: thresholds (T, N, F) are preregistered before examining data — values to be fixed in the pilot-design ticket, recorded here by amendment; every transition is itself a recorded, reversible decision; a rising false-accept rate after withdrawal drops the phase automatically; **no stage graduates while its evidence is self-attested** — the independent verifier principal (C2) is a hard dependency for Phase 2 on outcome-bearing stages.

## Amendment protocol

The pinned YAML is immutable in place. To change it: (1) open a PR editing this file AND adding `docs/program/NORTH-STAR-amendment-<N>.json` with `{"amendment": N, "old_sha256": ..., "new_sha256": ..., "reason": ..., "approver": ..., "date": ...}` AND updating `docs/program/pins.json`; (2) the guard test enforces chain contiguity (each amendment's old_sha256 equals the prior pin); (3) operator approval required (CODEOWNERS on docs/program/). A redrawn Destination is a new effort, not a resumption — per the wayfinder doctrine this map follows.

## Normalization rule (for the sha256 pin)

The pinned hash is sha256 over the fenced YAML block: all lines strictly between the ```yaml fence line and the closing ``` fence line, each line right-stripped of trailing whitespace, joined with "\n", with exactly one trailing "\n", UTF-8 encoded. The guard test (`tests/test_destination_pin_guard.py`) implements this identically.
