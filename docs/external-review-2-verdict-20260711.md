Validation method: one agent on all new repo claims (exact quotes), one on all 14 external tool facts (with links), the power analysis recomputed from scratch, and Slack corroboration of the key Unity-internal claim. Companion to `external-review-verdict-20260711.md` (yesterday's review, whose six findings this review correctly builds on).

There is no invocation method on the protocol at all**, which is why `AgentInvoker` (and `telegram_supervisor`, `hook_critic`, `agentic_executor`, the Cursor reviewer path — ~6 modules) hard-code providers. The model-agnostic gap is structural, not sloppy.

The fix literally exists one function above: the reserve path guards with `AND terminal_outcome_json IS NULL` (`state.py:1985`); complete omits it. One-line fix + rowcount branch for the discrepancy event.
- **NEW BUG 2 (confirmed, worse than stated):** `_terminate_process` signals only the process object while workers are spawned with `start_new_session=True` — so cancelled workers orphan their `claude`/`codex` child CLIs (no `killpg`). And the stale-lease reaper path (`_fail_spawned`) **never kills the process at all**: a job marked failed keeps executing.
- Overlay whitelist/path-restriction citations: exact.

**External facts: 12/14 confirmed with links** (Restate BSL 1.1; Temporal MIT + versioning; Phoenix ELv2; OTel GenAI semconv still "Development"; AutoGen→Agent Framework migration guidance; LangGraph durable execution; SWE-bench harness; Harbor task/env/agent/verifier + Terminal-Bench 2.0; Inspect AI; GEPA [arXiv:2507.19457](https://arxiv.org/abs/2507.19457) + dspy.GEPA; MIPROv2; OpenFeature; Argo Rollouts). **2 refuted: both 2026 arXiv IDs are wrong.** "Meta-Harness" is [arXiv:2603.28052](https://arxiv.org/abs/2603.28052), not 2603.05344 (that's a terminal-agents lessons paper); 2601.13200 is an *astrophysics* paper — the real harness-evolution reference is "Agentic Harness Engineering," [arXiv:2604.25850](https://arxiv.org/abs/2604.25850). **Power analysis: exact to the digit.** Recomputed independently (exact binomial, two-sided α=0.05): 80% power needs ~199 discordant pairs at a 60% win rate, ~90 at 65%, ~49 at 70%, ~30 at 75%; and the discreteness quirk reproduces exactly (n=49→81.0%, n=50→78.2%, n=60→83.8%). **This corrects yesterday's review and my endorsement of "≥50 discordant" as a universal target.** The pilot-first, estimate-discordance-then-fix-n procedure is the right design.

**Unity-internal claims: corroborated via Slack** (internal GitHub unreachable from here). ## What I keep (the review's core is right)

The **thin-kernel decision** and the non-negotiables list (schemas, adapters, hashes, gates, approval/rollback stay Supervisor-owned; frameworks may produce evidence but never accept runs, set claims, pick policies, or rewrite receipts). **Official oracles unforked** (SWE-bench harness, Harbor) — matches our prereg discipline. **Blinded Standards/Spec judges + outcome-aware adjudicator** — same conclusion as yesterday, now with the judge-bias citations attached. **The corrected experiment design** (unique task as unit, pilot→power→freeze-n, McNemar exact + Newcombe CI, three pinned model families with per-family reporting and a family GEPA never saw). **GEPA-first with control arms** (frozen policy, no-op, human, MIPROv2) — the no-op and human arms are what make an optimizer result mean something. **Optimizer isolation + five data partitions + candidate lifecycle** — this is the hidden-evaluation boundary our loop lacked a name for. **Deletion discipline** ("only after parity is proven"). **The ROI sentence worth framing: the scarce resource is not coding effort, it is trustworthy evidence.**

## Four changes, with reasons

1. **Fix the two new bugs now, not in a phase.** The terminal-overwrite guard is a one-liner mirrored from `state.py:1985`; the `killpg` + reaper-kill fix is hours. Both protect evidence integrity for every run that happens while the phases roll out. (The review lists the terminal fix under "change immediately" but buries the process-group fix in the bakeoff section — it's a today-fix.)
2. **Re-sequence days 0–30 to the experiment's critical path.** The review's own ROI table ranks reuse (#5) and the durable bakeoff (#6) *below* the paired experiment (#4), but its 30-day plan front-loads OTel + storage + retrieval + bakeoff alongside evidence repair. That's how measurement moments slip. Critical path only: freeze → data-path repair (its Phase 1 exit gates are excellent — adopt verbatim) → schemas/pins → blinded judges → off-arm pilot. Everything else runs parallel-optional and must yield on contention.
3. **Defer the durable-engine migration decision until after the day-60 readout.** The dispatcher was just hardened (Slice 10 + Phase W crash/resume tests green); Slack shows Restate brings its own failure modes (infinite retry loops); Restate's BSL 1.1 needs legal review; and the 18-test bakeoff matrix — which is excellent, keep it — answers an *operational* question, not the evidence question. Run the bakeoff in the background if capacity exists; migrate only if the readout says Supervisor is worth operating at scale.
4. **Constrain GEPA per overlay slot from day one.** Eevee's own data ([arXiv:2606.11182](https://arxiv.org/abs/2606.11182)) shows GEPA at −15.4 cumulative retention under a 4-task mixture — a single shared evolving prompt is the one configuration known to go net-negative. Our overlay is per-task-class slotted; GEPA must optimize one slot per experiment, never a global artifact. The review defers "EEVEE-style routing" until interference is measured but doesn't apply the same caution to its GEPA-first step; close that gap.

## ROI, simply

Every dollar and day spent before the data path is fixed buys evidence nobody can trust. Every dollar after pins + blinding + the off-arm buys an answer to the only question that matters: `incremental_successes = N × (success_on − success_off)`. The review's formulas are right; the order that maximizes them is: micro-fixes (hours) → freeze (days) → data path + schemas (a week) → blinded judges + pilot (a week) → powered paired run (weeks, VM-bound) → only-if-positive: GEPA behind partitions. Platform adoption (OTel, storage, retrieval, engine) is real ROI but *operational* ROI — it never outranks the experiment on the calendar.

## The goal, checked against this plan

- **Model-agnostic:** the validated crux is the missing *invocation* abstraction. Adding `invoke()` to `TargetAgentAdapter` and routing the ~6 hard-coded modules through it is the single change that makes "same task, any lead model" true — and the three-family experiment then proves it.
- **Measurably better:** the corrected power analysis is the honest price tag: at a 65% win rate expect ~90 discordant pairs, which at plausible discordance rates means several hundred paired tasks. Budget for that; don't buy a underpowered "success."
- **Auto-improving:** GEPA-with-controls, per-slot, behind hidden promotion partitions, canaried by OpenFeature-style sticky assignment, promoted only by humans — that is auto-*improvement* with the auto-*drift* failure modes designed out.
